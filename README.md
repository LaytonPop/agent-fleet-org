# agent-fleet-org

**agent 舰队的组织法：谁存在、各自拥有什么、向谁汇报。**

这是一份组织模型，不是一个运行时。它回答四个问题：舰队里有几级、每一级拥有什么、工作怎么流转、错误和异议怎么留下来。

当前版本：**v0.1（2026-11-01 冻结为记录点）**

## 为什么叫这个名字

- `fleet`：问题域，不是军事装饰。它是"多个 agent 组成的编制"这个说法的简称，和业界 agent fleet 对得上。
- `org`：仓库里装的是组织法（谁存在 / 拥有什么 / 向谁汇报），不是实现，也不是脚手架。
- 机制上的隐喻（列宁制的分工、纪律、汇报）只出现在文档里，见 [docs/00-为什么借列宁制.md](docs/00-为什么借列宁制.md)。它不进名字、不进目录、不进代码，也不涉及现实政治。

## 三条原则

违反任何一条，这个模型就不成立。

1. **隔离**：一个 session 一个机器人。独立上下文是独立判断的前提；把所有东西合并进一个万能 session，只会得到"什么都懂一点、什么都不专业"的总管。
2. **汇报**：每个单位必须有固定出口——固定格式、固定周期、固定去向。隔离不是 bug，**失联**才是 bug；没有出口的单位等于不存在。
3. **规则**：行动凭书面授权，不凭心情。规则有版本、有范围、可追溯；越界即停，停下来记一笔再谈。

两条工程天条：

- **证据分级**：每条结论标 `[原话]` / `[文档]` / `[源码]` / `[二手]` / `[假设]`。不确定就写不确定。
- **异议不合并**：两份结论矛盾的报告同时存档（未来的 `_disputes/`），不合成一份"看起来对"的东西。

## 四级形状（v0.1）

| 层级 | 是什么 | 拥有什么 | 有没有 session |
|---|---|---|---|
| 中央（Router） | 调度 + 汇总 + 对外 | 全局事件序、规则版本 | 有，一个常驻 session，**不执行** |
| 部委 | 疆域，不是机关 | 共享记忆域、预算、规则范围 | 无 |
| 部门 | 机关 / worker | session、目录、授权、inbox | 有，一 session 一机器人 |
| 班组 | 临时执行体 | 无 | 无（subagent，无地址） |

判词：**部委者，非会话也，乃疆域也。** 展开见 [docs/设计现状.md](docs/设计现状.md) §2.3。

## 当前停点

`Q-02`：**真 worker 要不要配地址？**

- 配到部门级：要能被找、被问、被中断，就必须有 session；
- 允许 subagent 也能被找：等于把 subagent 降级成部门；
- 不配地址、配订阅：不给人找它，而是让它订阅线程——线程归谁，谁处理。
