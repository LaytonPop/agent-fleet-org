# 为什么借列宁制

> 一句话：列宁制是**解释口径**，不是意识形态。它提供的是分工、纪律、汇报这类现成词汇，不是政治纲领。它只出现在文档里，不进仓库名、目录名和代码，也不涉及现实政治。

## 为什么需要一个这样的口径

讨论"多个 agent 怎么组织"时，最容易发生的坏事情是词汇混乱：

- `session`、`agent`、`机器人`、`worker`、`subagent`、`团队` 混着用，同一个词在不同段落指不同东西；
- 一说到"每个部门一个 agent"，就有人接"那不就是 subagent 吗"——把「能干什么」和「有没有地址」混为一谈。

列宁制的组织语汇恰好覆盖三层：**谁存在**（编制）、**谁向谁负责**（汇报）、**什么不能做**（纪律）。借它，是为了让讨论有稳定的词，而不是为了比喻谁。

## 借了三件可操作的东西

### 1. 民主集中制：采集分散，汇总集中

- 采集端：各部门独立接触各自的信息源，独立判断，各自写报告。
- 集中端：中央只收固定格式的报告，不逐条对话。
- 工程对应：每部门一个常驻进程 + 一个信息源 + 一个作业模板 + 一个周期；产物落固定目录（如 `00-inbox/<部门>/<日期>.md`）。
- 反例：中央试图和每个部门闲聊、实时指挥每一件事——那是聊天系统，不是情报系统。

### 2. 汇报制度：失联即故障

- 每个单位必须有固定出口：固定格式、固定周期、固定去向。
- 隔离（各 session 互不相通）是好事，它保证独立判断；**失联**（没有汇报）才是坏事。
- 工程对应：部门四件套（进程 / 信息源 / 模板 / 周期）。一个"部门"如果没有固定出口，它就不是部门，只是一次性查询。

### 3. 纪律红线：授权之外不做

- 能做什么、不能做什么、越界怎么办，必须写下来，并且可追溯。
- 工程对应：授权（Mandate）、版本化的规则（Policy）、决策门（歧义停给有权限的人）。
- 红线不是建议：越界即停，停下来记一笔，再回到有权限的人那里。

## 不借什么（越界清单）

1. **不借"先锋队掌握真理"的认识论。** agent 不知道自己错在哪；把它当真理持有者，就会稳定生产"自信的废话"。
   工程后果：必须保留异议——两份矛盾的报告同时存档，进 `_disputes/`，不合并成一份"看起来对"的结论。
2. **不借政治动员与斗争语言。** 本仓库不讨论现实政治；隐喻到此为止。
3. **不借"一个领袖说了算"。** 中央 Router 不执行具体工作，也不给工作质量打分；它只做调度与汇总——它没有"正确意见"，只有调度记录。
4. **不借"下级只是执行工具"。** 部门有自己的上下文和判断权，否则隔离就失去了意义。

## 用在哪些词上（术语边界）

| 借来的词 | 在这里指什么 | 不是什么 |
|---|---|---|
| 部委 | 疆域：共享记忆域 + 预算 + 规则范围 | 不是一级机关，没有 session |
| 部门 | 机关：有 session、目录、授权、inbox | 不是临时工位 |
| 班组 | 临时执行体（subagent） | 不是编制单位，不占名额、没有地址 |
| 中央 | 调度与汇总 | 不是裁判，不评价工作质量 |

判词：**部委者，非会话也，乃疆域也**——一个层级只有拥有不可分割的东西才成立；部委拥有的是"一块域"，不是"一次对话"。

## 什么时候该把这个隐喻收回

出现下面任一情况，说明已经超出借用边界，应回到对象模型（谁拥有什么）重新问：

- 开始把"部委"当成一个会思考、会决策的实体；
- 开始用"中央"给工作质量打分；
- 开始用"纪律"要求 agent 服从某个人，而不是服从一条可追溯的规则；
- 讨论里出现"谁更正确"，而不是"谁拥有哪部分事实"。
